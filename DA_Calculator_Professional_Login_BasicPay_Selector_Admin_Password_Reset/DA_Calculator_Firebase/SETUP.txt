D.A CALCULATOR - FIREBASE SPARK PLAN VERSION

WHAT THIS VERSION DOES
- Uses Firebase Email/Password Authentication for the Admin and the common user account.
- Only the configured Admin UID can enable or disable common-user access.
- Disabling access increments a Firestore session version. Connected common-user sessions are signed out.
- While access is disabled, the app checks Firestore and blocks common-user sign-in.
- The Admin can request a Firebase password-reset email for the common user's registered email.
- When the Admin requests a reset, common-user access is disabled and the session version is incremented, signing out connected common-user sessions.
- After the common user completes the secure email reset link, the Admin must manually re-enable common-user access.
- No Cloud Functions are included or required.

IMPORTANT LIMITATIONS
- Firebase Authentication does not allow a static browser app to safely set another user's password directly. This version uses Firebase's secure password-reset email flow instead.
- The Admin must enter the exact email address registered to the common-user Firebase Authentication account. The email must be enabled/authorized for password-reset delivery in the Firebase project.
- The Admin does not see or choose the new password. The common user sets it using the secure Firebase email link.
- This static calculator runs in the browser. The login screen is an app access gate, not a tamper-proof DRM system; a technically skilled person who modifies the downloaded HTML can bypass client-side UI. Firestore writes remain protected by the rules below.
- Connected devices receive revocation in real time. A device that is offline cannot receive the sign-out event until it reconnects; on next online login/check, the app verifies the current access flag.
- The app allows only the two configured UIDs below.

FIREBASE CONSOLE STEPS
1. Keep the project on the Spark plan.
2. Confirm Authentication > Sign-in method > Email/Password is enabled.
3. Confirm both Admin and common-user accounts exist under Authentication > Users and their UIDs match the IDs above.
4. Open Firestore Database > Rules.
5. Replace the rules with the contents of firestore.rules and click Publish.
6. The Admin signs into the calculator once. This initializes the security/session document automatically.
7. In the Admin panel, use Disable common-user access / Enable common-user access.
8. To reset the common user's password, enter the common user's registered Firebase email and click Send password reset email.
9. The app disables common-user access and revokes connected sessions before requesting the email. After the user completes the reset link, the Admin clicks Enable common-user access.

HOSTING
- The site files can be hosted as a static site. If using Firebase Hosting, deploy the hosting and rules configuration with Firebase CLI from a computer or a suitable cloud development environment:
  firebase deploy --only hosting,firestore:rules
- Do NOT deploy Cloud Functions. This bundle intentionally has no functions configuration.

SECURITY
- Never put account passwords, service-account private keys, or Admin SDK credentials in this repository.
- The Firestore rules identify the Admin by Firebase Authentication UID. The Admin UID is an identifier, not a password.
